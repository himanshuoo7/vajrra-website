Spec stage

Before any dataset: the define.xml.

We also ran CDISC’s own Define-XML v2.1 ADaM example from the official release package: it passes the 135 schema rules, and three specification rules flag real deviations in it — two variables without the CDISC codelist their standard requires, and an ADSL description that isn’t the standard one.

How we ran it

  • ADaM Preflight 0.2 with the CDISC ADaM Conformance Rules v5.0, CDISC Controlled Terminology 2025-03-28 and the PMDA Study Data Validation Rules v6.0. The ADaMIG version was chosen for each input, never assumed.
  • Pilot datasets: the updated CDISC pilot submission package (ADaM XPT files, with SDTM DM, AE and EX), checked against ADaMIG 1.0. Planted errors were applied to a copy in memory; the published files were not changed.
  • Ambiguous rule sentences are read conservatively and the reading is shown in the report; a finding reported by an official rule and a built-in check appears once, under the official rule.
  • ADaM Preflight supports qualified review; it doesn’t replace it. A clean report means the rules found nothing, not that the analysis is right.
